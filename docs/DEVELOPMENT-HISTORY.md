# 月下水镜 · 隐月

单手摄像头交互的 3D 塔罗作品。Three.js 渲染水镜、烛光与卡牌，MediaPipe 在本地 Worker 中识别手部，摄像头画面不上传、不录制。无需 API 密钥或构建步骤。

## 运行

在此目录执行 `python3 -m http.server 8877 --bind 127.0.0.1`，打开 http://127.0.0.1:8877/ 。摄像头要求 localhost 或 HTTPS，不能通过双击 HTML 运行。

## 体验

1. 点击开启摄像头并授权，把一只手自然放进镜头。无需摊掌、拂水或停稳。
2. 牌影会自动出现，水面光圈跟随手的位置；拇指与食指轻捏一下确认。
3. 松开两指即可，系统自动完成约 0.68 秒的捞起动画与落位，保留出水和滴水音效。
4. 在舒适的位置再次轻捏，连续选出三张牌后统一揭晓。

手势位置作指数平滑；短暂丢失追踪有 0.4 秒容错。捏合有开合阈值差与短时间去抖。持续捏合不会连抽；下一张必须先松开两指。已经确认的牌即使追踪丢失也会完成动画，未确认的牌继续等待。鼠标体验采用同一流程，点击即可选牌，不必拖动。

78 张韦特体系塔罗牌（22 张大阿尔卡那、56 张小阿尔卡那），正逆位独立随机、各 50%，每轮无放回抽三张。牌阵为过去、现在、未来可能的发展方向。传统牌义与原图依据见 TAROT-SOURCES.md。

## 针对问题的 AI 解读（2026-10-27）

填写问题并抽齐三张牌后，结果页会自动请求 `/api/reading`，显示问题回应、三张牌各自与问题的联系、三牌综合、行动建议及反思问题；文本保存包含这些内容。空问题不请求 AI；失败保留原牌并可重试。再次抽牌会取消旧请求，防止旧解读覆盖新结果。

服务端从 `tarot-knowledge.json` 按三个牌 ID 读取可信牌义，不接受客户端自定义牌义。知识库包含 78 张牌的传统图像象征、现代中文正逆位牌义与 468 条牌位基础解释，与 `cards.js` 一致。情境指引涵盖关系、工作学习、选择与自我成长，由模型结合问题判断。

启用方式（密钥只在本机终端设置，不要填写到网页或提交到代码）：

```sh
export OPENAI_API_KEY='你的 API 密钥'
# 可选，默认使用 gpt-4.1-mini；需支持 Responses API 的结构化输出
export OPENAI_MODEL='gpt-4.1-mini'
python3 preview-server.py stop
python3 preview-server.py
```

打开 http://127.0.0.1:8877/ 。需通过此 Python 服务访问，静态托管不提供解读接口。若没有配置密钥，页面会明确提示未启用，不用固定文案冒充 AI 解读。服务仅监听本机，问题与牌阵会发送到 OpenAI API；请求设置 `store: false`，应用不保存问题或生成结果到服务器文件。浏览器的文本导出由用户主动保存。

接口采用官方 Responses API 的严格 JSON Schema 输出并再次验证；拒绝空问题、重复牌、越界 ID、过长请求和外站 Origin。密钥不返回前端，错误信息不透传上游响应。服务端最多同时处理两个生成请求；前端取消不能保证终止已经发送的上游生成。

验证：`python3 -m unittest test_tarot_api.py`、`node reading.test.mjs`，以及现有牌义、抽牌和手势测试。接口成功与失败路径使用模拟上游验证；真实模型生成需要有效 API 密钥和网络，当前未完成真实调用验证。

## DeepSeek 解读服务

当前本地配置已选择 DeepSeek 官方接口 `https://api.deepseek.com/chat/completions`，模型名沿用用户配置 `deepseek-v4-flash`。它与 Codex 中的 Responses 接口属于同一官方服务，本项目采用 Chat Completions 的 JSON 输出并在服务端校验完整结构。

在 `.env` 中设置：

```dotenv
READING_PROVIDER=deepseek
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_API_KEY=填写自己的DeepSeek密钥
```

不要把旧的 OpenAI 密钥放到 `DEEPSEEK_API_KEY`。模型平台的余额和密钥独立管理；密钥在 DeepSeek 官方平台创建。本地 `.env` 保存后立即生效。问题及三张牌发送至 DeepSeek，摄像头画面不发送。配置与解析适配已有模拟接口测试；真实调用需填入有效 DeepSeek 密钥。

## 水下牌池与握拳选牌（2026-10-27）

每轮将 22 张牌洗牌后抽取 7 张，分别绑定水下七个牌背。牌拥有独立位置、平移与旋转惯性，张开的手掌只向附近牌施加随距离衰减的水流；停止拨动后自然减速，边缘约束和轻微排斥避免挤成一团。靠近约一个牌宽时高亮并缓慢上浮，保留切换滞后以减少抖动。

张开手至少 160ms 后可握拳选牌；连续约 160ms 的握拳且附近有牌才会选中。指向手势、短暂收指、无目标握拳都不会抽牌。选中时才把该实体牌的身份传给 Spread，牌从实际水面位置捞起，剩余牌留在水中，持续握拳不会重复选牌。追踪丢失不会撤销已确认的捞起动画。

`pool.js` 为独立的牌池物理逻辑，`pool.test.mjs` 验证局部水流、惯性衰减、实体牌身份、移除和重置；`gesture.test.mjs` 验证握拳与张手、短噪声、无目标与持续握拳保护。浏览器通过仅供验证的 `?interaction=mouse` 模式走通三张不同牌从水中捞起到结果页；正常首页仍只提供摄像头入口。真实摄像头手势的舒适范围需结合使用者光照与姿势体验，不把鼠标模拟视为真实手部识别测试。


### 牌池密度与握拳跟进调整

水下改为全部22张真实牌，按向外扩散的错落分布铺满水镜，缩小单张牌并允许轻微重叠。握拳开始时锁住最近的高亮目标，掌心收拢位移不再使目标跳走；悬停位置做平滑。识别容许少量指节偏差，连续确认缩至约100ms，偶发的不确定帧只缓慢衰减确认进度。张手重置与持续握拳防连抽仍保留。手势检测提交间隔由65ms缩至45ms，捞起动画约620ms，落位等待520ms。实际耗时仍受模型推理速度与设备影响。

### 手掌够不到牌、握拳抓空的修正

摄像头掌心位置改取腕点与三个掌指关节点的平均值，避免依赖单个关节点；镜头中央约54%的宽高映射到完整水面，并限制光标留在水镜内。悬停范围由0.53扩大到0.86世界单位，保持目标的范围由0.67扩大到1.03，位置平滑改为更快的响应。慢速靠近时水流不再推开当前目标，目标牌主动减速，握拳时保持目标锁定。放宽完整握拳的单指偏差容忍，同时保留指向手势排除和张手重置。

光标略放大，未选中为浅蓝、已有目标为金色，细金线连接当前目标，便于识别实际选择对象。新增测试检查中央手部活动范围可达水镜边缘、收指不改变掌心坐标、慢速靠近不推走目标、目标减速效果。实际摄像头识别舒适度仍需用户现场体验，模拟与单元测试不替代真实手部测试。


## 完整牌库与正逆位修正（2026-10-27）

补齐权杖、圣杯、宝剑、星币四组各 14 张，共 78 张。每次选中牌时，使用浏览器加密随机源独立确定正逆位（各 50%）；同一轮三张不重复，不强行保证正逆位混合。方向只生成一次，结果、牌面、AI 请求、重试及文本导出均使用这一方向；再次抽牌会重置。

`cards.js` 保留大牌数据并从 `deck-expansion.js` 加载小牌及逐牌逆位解释。`tarot-knowledge.json` 为服务端镜像，前后端一致性由测试验证。新增 56 张图像的原书文件名映射见 `assets/cards/manifest.json`。水中牌面缩小以适应 78 张牌。

解析按“问题判断→各牌的图像和牌义依据→三牌之间的推进或冲突→可执行验证”组织。逆位区分受阻、过度、内化与松动，不简单视为正位反义。未提问、生成中或生成失败时，基础牌义不冒充针对问题的 AI 综合结论。

服务端接受 `cards: [{id: 0, reversed: true}, ...]`，严格校验三个不同 ID（0–77）和布尔方向；兼容旧客户端的纯数字 ID（视为正位）。更改服务端或知识库后需重启 `python3 preview-server.py stop` / `python3 preview-server.py`。

结果页优先显示针对问题的 AI 解析；逐牌常规解释标为“本次牌阵 · 牌面基础”，避免将预写牌义误认成个性化分析。
